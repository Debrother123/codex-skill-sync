# 接入与同步约定

## 首次发布与接入

仓库应先包含 `skills/codex-skill-sync/` 的完整工具：SKILL.md、说明、脚本与启动器。其他电脑或智能体获取后先读 SKILL.md，自行识别目录、检查依赖、适配并执行 bootstrap。仓库暂时没有文件或没有认证时可用完整 ZIP 先离线接入。

初始化会安装自身并生成 `Skills同步助手-<profile>.command`（Mac）或 `.bat`（Windows）。已有通用入口可以继续保留。程序源码位于实际 skills 目录，不依赖下载目录；用户删除 ZIP 不影响安装版。不要在测试目录生成正式入口。

重复参数初始化复用既有登记和入口。相同 ID 指向不同目录、相同目录被另一环境登记、已有同名但不同内容的管理 skill 或入口时保留现场，接入智能体比较后处理，不默默覆盖。

## 本地环境与版本来源

每个环境有独立工作副本、名单、安装基线和备份。环境 ID 仅用于本机管理；远程版本名决定哪些机器共享同一份适配源码。

- 默认 `shared`：源码在 `skills/<name>`，适合跨智能体共用的 skills。
- 专用版本如 `workbuddy`：源码在 `variants/workbuddy/skills/<name>`，使用同一专用版本名的其他机器可以同步它。
- 管理工具 `codex-skill-sync` 始终在 `skills/codex-skill-sync`，避免各环境找不到共同入口。

当前版本每个环境选择一个版本来源，不支持同一环境逐个 skill 混用来源。专用版本尚未有 skill 时，不静默用共享版本替代：由接入智能体读取共享原件、在目标安装目录完成必要适配，再发布到该专用版本。用户无需为了例行核验和适配额外批准；上传范围仍以明确选择为准。

若共享版本只需修正机器绝对路径，优先改成变量/本机配置，保留可移植源码。确实不同的智能体调用可以使用专用版本。不要为了消除差异直接重写同步基线；先保留双方并解决内容差异，再让程序登记真实一致的哈希。

## 范围

列表来自当前环境本机目录、对应版本的远程源码和共享管理工具。勾选名单在各环境独立保存，取消选择只停止管理。Git fetch 获取整个仓库历史，但上传与安装只处理所选 skill。

顶层链接型 skill 会出现在清单中并显示真实路径。首次同步需明确登记真实目录（本机配置 link_targets），目标改变后重新确认；断链显示恢复提示。下载更新真实目录并保留入口链接，旧内容仍备份。同一真实目录的多个入口合并显示；重复/重叠批量目标停止。内部文件/子目录链接仍不跟随。目录依赖由接入智能体检查。系统/插件缓存默认不纳入本工具管理。Agent 档案、个人记忆、登录凭据、Obsidian 内容及 Codex 全局配置不是此工具的同步范围。

## 状态与恢复

默认状态根目录 `~/.codex-skill-sync/`；`profiles.json` 保存登记与上次环境，`profiles/<id>/` 保存各自配置、选项、工作副本、基线与备份。旧版顶层 config.json 继续由 legacy 环境使用。不能把这份状态复制给另一台电脑。

仓库脏状态、未推送提交或分叉时停止。当前智能体按实际差异恢复普通 Git 工作流，不强推、不删除本机改动。完成上传后独立读取远程 SHA；完成安装后核对文件哈希，运行依赖的可用性由智能体另行验证。

目前使用 Python 3.9+ 标准库和 Git，Tkinter 提供勾选界面。文件扫描能发现部分常见敏感文件，不等于完整隐私审计。Windows 与 WorkBuddy 的实际验收由当地智能体执行，不能用 Mac 的测试结果代替。

## 工具源码与个人数据分开

公开工具源码： https://github.com/Debrother123/codex-skill-sync

此仓库只发布同步工具。个人 skills 应存放在用户自己的数据仓库中，可保持私有；GUI 的“连接 GitHub”应填写该数据仓库地址。不要为了安装工具更改个人仓库的可见性。

初次安装：从公开仓库下载 `skills/codex-skill-sync/` 完整目录，读取 SKILL.md 后执行 bootstrap。公开源码下载无需私人仓库登录；访问个人数据仓库或提交更新仍需本机授权。

后续更新工具：由接入智能体获取公开仓库最新版本，比较本机改动、保存旧版备份、完整替换工具目录，复用原 profile、state-home 和快捷方式配置，再执行 `bootstrap.py init ... --refresh-launcher` 并验证。保留数据仓库地址、勾选名单和状态；本机有未知改动时先比较，不直接覆盖。更新后重新打开窗口。

当前 GUI 每个环境只连接一个数据仓库，不会自动同时拉取公开工具仓库。只有数据仓库也保存了工具的副本时，才可以通过勾选 `codex-skill-sync` 更新该副本；它可能落后于公开上游。公开上游更新由智能体执行上述流程，不要把个人 skills 上传到公共工具仓库。
