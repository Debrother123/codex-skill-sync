# Skills 同步助手

用户勾选哪些就只同步哪些。GitHub 保存共享源码；每个本机智能体环境分别保存目录、勾选名单、基线与备份。同步工具自身先发布到仓库，供其他电脑或智能体读本文件后接入。

仓库：`https://github.com/Debrother123/codex-skill-sync.git`。核对实际权限和远程内容，不把文档视作已经上传的证据。

运行时、认证、无头命令、冲突处理和行尾策略见 [接入故障与操作说明](references/troubleshooting.md)。

## 首次加载：由当前智能体执行

先读 [接入与同步约定](references/sync-contract.md)。运行 `scripts/bootstrap.py list` 检查本机是否已经登记；已登记且路径正确就复用，不重复安装、不重复问用户目录。

尚未登记时，由你完成以下工作，不将常规命令转交用户：

1. 识别当前操作系统、智能体，以及它实际读取的 skills 目录。不要把 Codex 路径猜成 WorkBuddy 路径。检查 Git、Python 3.9+ 与 Tkinter；初始化自动探测，缺少 Tk 时寻找已有 GUI Python 或明确使用 CLI，不假定 WorkBuddy 内置 Python 能显示窗口。
2. 按用户已有要求确定快捷方式目录。使用当前机器上用户指定的目录，不从其他机器的说明中照搬绝对路径。缺少这项信息时只问位置。
3. **兼容性核验和必要适配由接入智能体自行完成**：自行检查 skill 格式、路径、工具调用、运行依赖并修改与验证。在用户已授权安装或更新的范围内完成例行适配。保留原文件备份；不要修改认证、扩大远程同步名单，或覆盖未知的双方改动。
4. 为环境选择稳定的本地 ID，如 `mac-codex`、`mac-workbuddy`、`windows-codex`。这些只是示例，不代表环境存在。运行：

   ```text
   python scripts/bootstrap.py init --profile <环境ID> --name <显示名称> --skills-dir <实际目录> --shortcut-dir <用户指定目录> [--variant shared或专用版本名] [--state-home <本智能体独立状态根>] [--python-exe <实际Python>] [--git-exe <实际Git>]
   ```

   所有路径参数需按当前 shell 正确引用。脚本将安装本 skill 到目标目录的 `codex-skill-sync` 子目录、登记本机环境、创建启动入口。Mac 是 `.command`，Windows 是 `.bat`，其他系统使用 shell 入口；重复运行同样参数可安全复用。离线也可初始化，GitHub 认证不阻塞安装和快捷方式创建。
5. 启动 `scripts/skill_sync_gui.py --profile <环境ID>`，核对目标环境、skills 列表和快捷方式。连接 GitHub 后由用户勾选同步项。程序支持多个环境切换，选择在未连接 GitHub 时也能保存。
6. 只在实际核验后报告：本机初始化、智能体适配、GitHub 连接、上传/安装是不同状态。不得宣称未操作的其他电脑已就绪。

## 日常使用

图形界面：选择目标智能体 → 按名称/功能搜索并组合筛选 → 勾选 skills → 预览/上传或接收。每次操作重新选择全部勾选项或当前可见勾选项，不记忆范围；执行后保留全部勾选名单。上传支持已有 skill 再次更新，可填写提交说明。`scripts/skill_sync.py --profile <环境ID>` 是数字菜单备用入口；追加 `sync --direction download --yes` 可无头同步同一名单，不加载 Tk。

“刷新清单”读取远程并安全快进仓库工作副本，清单为空也能发现新 skill。它不会安装任何 skill。取消勾选不删除本机文件或远程源码。新增 skill 不自动纳入。

共享版本位于 `skills/<name>`；专用版本位于 `variants/<variant>/skills/<name>`，两个来源不隐式互相覆盖。`codex-skill-sync` 自身始终从共享位置更新。当前智能体可将平台无关修正用于共享版本，专用适配放在专用版本；详细流程见同步约定。

## 更新与异常

上传前检查差异和所选文件，接收前比较安装基线。脚本备份后替换并核对文件哈希。遇到首次同名差异、双端冲突、仓库脏状态或未推送提交时保留现场，由当前智能体使用 diff/resolve 正式流程比较、适配、验证后继续，不手改基线、不自动强推或 reset。

自更新按完整目录执行，保留旧版备份，程序重启后加载新版。智能体修改本工具时需保持共享入口跨平台；不要为了适配某个环境把其他环境的调用删除。

本机状态默认在 `~/.codex-skill-sync/`，也可设置 `SKILL_SYNC_HOME`；不得上传此目录、认证或令牌。旧版配置会作为“原有环境”保留。两台电脑分别认证，不迁移凭据。不同智能体沙箱建议使用独立 `SKILL_SYNC_HOME`；生成的启动器固定对应状态根。

## 完成报告

说明当前环境与目录、快捷方式、勾选范围、实际远程 SHA、安装/适配验证、备份位置和未完成事项。一般操作沿用用户授权，只有缺失的实际目录、本人登录、冲突决策或权限边界才需要用户介入。

## 工具源码与个人数据分开

公开工具源码： https://github.com/Debrother123/codex-skill-sync

此仓库只发布同步工具。个人 skills 应存放在用户自己的数据仓库中，可保持私有；GUI 的“连接 GitHub”应填写该数据仓库地址。不要为了安装工具更改个人仓库的可见性。

初次安装：从公开仓库下载 `skills/codex-skill-sync/` 完整目录，读取 SKILL.md 后执行 bootstrap。公开源码下载无需私人仓库登录；访问个人数据仓库或提交更新仍需本机授权。

后续更新工具：由接入智能体获取公开仓库最新版本，比较本机改动、保存旧版备份、完整替换工具目录，复用原 profile、state-home 和快捷方式配置，再执行 `bootstrap.py init ... --refresh-launcher` 并验证。保留数据仓库地址、勾选名单和状态；本机有未知改动时先比较，不直接覆盖。更新后重新打开窗口。

当前 GUI 每个环境只连接一个数据仓库，不会自动同时拉取公开工具仓库。只有数据仓库也保存了工具的副本时，才可以通过勾选 `codex-skill-sync` 更新该副本；它可能落后于公开上游。公开上游更新由智能体执行上述流程，不要把个人 skills 上传到公共工具仓库。

## 链接目录接入

顶层符号链接会显示在原环境清单，首次同步需要确认实际目录；UI 提供“管理此目录”，CLI 使用 `--profile ID link --skill NAME --target 真实绝对目录 --yes`。授权只存在当前环境配置，不能跨机器复制。上传同步内容，接收更新真实目录并保留入口链接。链接目标变化后停止并重新确认；内部嵌套链接仍禁止。不要再通过为每个链接新建环境来绕开识别限制。
