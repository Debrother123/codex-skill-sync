# Skills 同步助手

先选择智能体环境，再勾选需要同步的 skills。每个环境分别保存目录、名单、版本记录与备份。

## 首次在另一台电脑或智能体接入

把仓库地址或完整资料包交给当地智能体：

> 请阅读 codex-skill-sync 的 SKILL.md，完成本机首次接入。自行核验并修改必要的平台、路径和工具调用适配；确认你实际使用的 skills 目录；在我指定的位置创建启动快捷方式。不要将常规命令转交给我。已配置的环境直接复用。

仓库： https://github.com/Debrother123/codex-skill-sync

智能体会安装工具、检查 Git/Python/Tkinter、登记环境并生成启动入口。缺少本机快捷方式位置时会问你一次。安装和初始化可离线完成；GitHub 访问另行检查，每台电脑独立认证。

## 打开和使用

Mac 双击生成的 `Skills同步助手-<环境ID>.command`，Windows 双击 `.bat`。已有通用 `Skills同步助手.command` 仍可使用，默认打开上次选择的环境。

1. 在“当前环境”选择 Codex、WorkBuddy 或其他已经登记的智能体。
2. 点击“刷新清单”，读取 GitHub 最新源码清单。
3. 勾选需要的 skills，名单自动保存在该环境。
4. 本机修改后点击“上传到 GitHub”；要接收更新点击“从 GitHub 更新”。
5. 查看变更列表，确认执行，日志显示结果和备份。

未勾选的 skills 不上传、不安装；取消勾选不删除文件。获取 Git 历史仍会下载整个仓库。两台电脑或两个智能体不必勾选相同项目。

## 多智能体

点击“添加智能体 / 首次初始化”，填写已由智能体确认的目录、显示名称和稳定环境 ID，再选择快捷方式目录。程序不会猜 WorkBuddy 的目录，也不会假定它与 Codex 配置相同。

默认共用 shared 源码。需要保留智能体专用改动时，接入智能体可使用专用版本名，例如 workbuddy。当前每个环境使用一个版本来源；管理工具自身始终共用同一版本。

## 自更新与冲突

勾选 `codex-skill-sync` 可以更新工具本身，完成后关闭并重新打开窗口。工具不自动安装第三方应用；兼容性核验、修改和运行验证由接入智能体完成。

首次同名内容不同、双方修改、未推送提交或 Git 认证失败会停止，保留现场，交给当前智能体检查。不得通过强推、reset 或随意清空同步记录解决。

本机状态默认在用户目录 `.codex-skill-sync`，不能复制给另一台电脑。源码安装在实际 skills 目录；删除下载包不影响已安装的工具。

## 修复版新增操作

“差异与冲突处理”可查看逐文件差异、保存双方副本、采用本机/GitHub 版，或登记智能体已合并的目录。“认证检查”说明当前仓库是否可读。启动器固定已验证的 Python 和 Git 路径，不再要求 Windows 安装 py 命令。没有 Tk 时提供 CLI 入口。

新增安装没有旧文件可备份；覆盖才生成旧版备份。每次成功同步另有回执。详细命令、独立状态根、设备登录和依赖检查见 references/troubleshooting.md。


## 搜索、筛选与再次提交

- 搜索下拉框可切换“名称”或“功能”；功能读取 SKILL.md 的 description，并在列表显示。
- 同步状态、勾选状态、来源可组合筛选。状态来自上次获取的仓库内容，点击“刷新清单”获取 GitHub 最新变化。
- “全选当前结果／取消当前结果”只影响当前可见项；“清空全部勾选”影响全部名单。
- 每次预览、上传、接收都重新询问：全部勾选项（含隐藏项）或当前可见勾选项。显示数量，不预选、不记住范围；取消不执行。
- “上传／提交更新”同时支持首次上传与已上传 skill 的后续更新；可填写更新说明，留空自动生成。无变化项自动跳过。
- 上传后保留勾选名单。仅操作可见项也不会取消隐藏项的勾选。

## 工具源码与个人数据分开

公开工具源码： https://github.com/Debrother123/codex-skill-sync

此仓库只发布同步工具。个人 skills 应存放在用户自己的数据仓库中，可保持私有；GUI 的“连接 GitHub”应填写该数据仓库地址。不要为了安装工具更改个人仓库的可见性。

初次安装：从公开仓库下载 `skills/codex-skill-sync/` 完整目录，读取 SKILL.md 后执行 bootstrap。公开源码下载无需私人仓库登录；访问个人数据仓库或提交更新仍需本机授权。

后续更新工具：由接入智能体获取公开仓库最新版本，比较本机改动、保存旧版备份、完整替换工具目录，复用原 profile、state-home 和快捷方式配置，再执行 `bootstrap.py init ... --refresh-launcher` 并验证。保留数据仓库地址、勾选名单和状态；本机有未知改动时先比较，不直接覆盖。更新后重新打开窗口。

当前 GUI 每个环境只连接一个数据仓库，不会自动同时拉取公开工具仓库。只有数据仓库也保存了工具的副本时，才可以通过勾选 `codex-skill-sync` 更新该副本；它可能落后于公开上游。公开上游更新由智能体执行上述流程，不要把个人 skills 上传到公共工具仓库。
